## Что это

РосПанель — самостоятельная панель для [Xray-core](https://github.com/XTLS/Xray-core). Она управляет пользователями, протоколами, подписками, маршрутизацией, тарифами и резервными копиями через веб-интерфейс. При необходимости к мастеру подключаются дополнительные ноды. Панель и Xray работают на вашем сервере; VPN-клиент в состав проекта не входит.

Один бинарник включает веб-интерфейс и API. Для панели доступны автоматические TLS-сертификаты через ACME, в том числе для IP-адреса при поддержке центром сертификации. Для **переезда мастера требуется домен**: прежние ссылки подписок сохраняются благодаря переключению его DNS-записи.

## Установка

### Скрипт и systemd

На Linux-сервере выполните:

```bash
curl -Ls https://raw.githubusercontent.com/Shu1t3/rospanel-shu1t3/main/install.sh | sudo bash
```

Скрипт скачает релиз, установит сервис и предложит указать домен. Если домена нет, оставьте поле пустым для работы по IP. Домен можно передать заранее через `ROSPANEL_HOST`.

Для ручной установки:

```bash
curl -fsSL -o rospanel https://github.com/Shu1t3/rospanel-shu1t3/releases/latest/download/rospanel-linux-amd64
chmod +x rospanel
sudo ./rospanel install
journalctl -u rospanel | grep -A6 FIRST-RUN
```

Для ARM замените `amd64` на `arm64`. Установщик выводит адрес панели в журнал. Первый вход: `admin` / `admin` по пути `/rospanel/`; мастер настройки потребует сменить пароль и предложит установить секретный путь. После смены пути сохраните новый адрес: по корню сайта форма входа не открывается.

### Docker

```bash
docker run -d --name rospanel \
  --network host \
  --cap-add NET_ADMIN \
  --device /dev/net/tun \
  -v rospanel-data:/data \
  ghcr.io/shu1t3/rospanel-shu1t3:latest
```

`NET_ADMIN` и `/dev/net/tun` нужны для AmneziaWG и других возможностей, которым требуется TUN. Для постоянной установки подготовьте доступ к данным и перезапуск контейнера средствами Docker.

### Переход с AppsGanin/rospanel

Перед переходом сохраните `/var/lib/rospanel` с остановленного сервиса. Затем запустите установочный скрипт форка и проверьте `rospanel status`, пользователей и старые ссылки подписок. Директорию данных не удаляйте до проверки. [Руководство по переезду](docs/MIGRATION.md) описывает перенос уже работающего мастера РосПанели между серверами.

## Ноды

В панели откройте **Сервера → Добавить ноду** и выполните выданную команду на новом сервере. Токен присоединения одноразовый и действует 24 часа. Доступна также установка по SSH. Ноде нужен исходящий доступ к мастеру; клиентские подключения приходят на саму ноду. Для нестандартного TLS панель может предложить установку с `--insecure` — используйте это только для доверенного мастера.

Ноды получают конфигурацию и пользователей от мастера. Статус локального агента проверяется командой `rospanel node status`. Контейнерную ноду обновляйте новым Docker-образом с пересозданием контейнера; её данные должны оставаться на постоянном томе. При переезде мастера его публичный домен сохраняется, поэтому повторное присоединение нод обычно не требуется.

## Переезд мастера

Функция рассчитана на мастер с **доменом**, через который уже выданы подписки и подключены ноды. Технический адрес нового сервера (IP:порт) используется только для связи между мастерами и не попадает в ссылки клиентов.

1. На старом мастере откройте **Управление → Переезд мастера**, укажите адрес кандидата и режим изменения DNS.
2. Запустите на новом сервере команду установки кандидата, которую выдаст панель. Токен сопряжения действует 15 минут.
3. Проверьте доступность кандидата из панели и отдельно проверьте его сетевые порты, сертификат для публичного домена и работу протоколов. Встроенные проверки не заменяют эти проверки на новом сервере.
4. После переключения обновите A/AAAA-записи домена, если выбран ручной режим DNS. Убедитесь, что подписка и VPN работают через прежний домен.
5. Сохраняйте старый сервер на время обновления DNS-кэша и отключайте его после проверки клиентов и нод.

Перед переключением сделайте независимую резервную копию. Возврат DNS на старый сервер после появления новых данных на новом мастере может привести к их потере. Подробности и аварийное восстановление: [руководство по переезду](docs/MIGRATION.md).

## Возможности

### Подключения и подписки

- **Протоколы:** VLESS Vision, VLESS XHTTP REALITY, Hysteria2 с переключением портов, AmneziaWG 3.1; доступны собственные inbound-конфигурации.
- **TLS и маскировка:** ACME-сертификаты, домены прикрытия и настройки транспорта через панель.
- **Пользователи:** лимиты трафика и скорости, сроки действия, группы, ограничения по IP и опциональная привязка устройств по HWID.
- **Подписки:** форматы для популярных клиентов, правила, ротация токена, режим обслуживания и настройка отображаемых серверов.
- **Внешние подписки:** импорт и использование внешних прокси; поддержка Happ Subscription (crypt1–5 и outbounds).

### Сеть и управление

- **Маршрутизация:** правила выхода, WARP, Opera и пулы прокси с контролем доступности и ограничением прямого выхода.
- **Мультинода:** отдельные параметры серверов, распределение пользователей и наблюдение за состоянием нод.
- **Тарифы и оплаты:** планы, провайдеры платежей и проверка статуса оплаты. Доступность конкретного провайдера зависит от его API и вашей настройки.
- **Администрирование:** роли, TOTP, аудит действий, резервные копии и восстановление.
- **Интеграции:** Telegram-бот, HTTP API, MCP, метрики Prometheus и [дашборд Grafana](docs/grafana/rospanel.json). Описание API: [docs/api.md](docs/api.md).
- **Эксплуатация:** диагностика, обнаружение злоупотреблений, уведомления, брендинг и интерфейс на русском и английском языках.

## CLI

```text
rospanel install                 установить и запустить systemd-сервис
rospanel uninstall [-y]         удалить сервис с сохранением данных
rospanel backup [файл]          создать резервную копию
rospanel restore [-y] <файл>    восстановить данные из копии
rospanel disaster-recover --from <файл> [--passphrase <пароль>]
                                 восстановить мастер после аварии
rospanel node install --join '<URL>'  присоединить ноду
rospanel node status            проверить локальную ноду
rospanel node set-panel <URL>   сменить адрес мастера для ноды
rospanel node uninstall [-y]   удалить сервис ноды
```

Восстановление из резервной копии требует перезапуска сервиса. Команды установки и управления сервисом выполняются с правами root. Актуальные параметры доступны через `rospanel help` и справку конкретной команды.

## Архитектура

Мастер хранит состояние в SQLite, отдаёт веб-панель и API, управляет Xray и синхронизирует ноды. Нода запускает Xray и локальный агент; связь с мастером инициирует сама нода. Для подписок и связи нод с мастером используйте стабильный публичный домен.

## Разработка

Нужны Go версии из [go.mod](go.mod), Node.js и npm. Веб-интерфейс находится в `web/`.

```bash
cd web && npm ci && npm run build
cd ..
go test ./...
```

История изменений — в [CHANGELOG.md](CHANGELOG.md), правила коммитов — в [.agents/rules/changelog-and-commits.md](.agents/rules/changelog-and-commits.md).
