# RosPanel Code Review Checklist

Используйте этот навык при подготовке Pull Request, перед слиянием изменений в `main` или по явному запросу на аудит кода RosPanel.

## Маршрутизация вспомогательных ресурсов
- `scripts/pre-review.sh` — запуск `gofmt`, `go vet` и `golangci-lint` перед ручным анализом.
- `assets/review-template.md` — шаблон структурирования замечаний (Must Fix / Should Fix / Nits).
- `references/WEB-SERVER.md` — паттерны работы HTTP-сервера, контекстов и корректного завершения (graceful shutdown).

---

## Порядок проведения ревью

1. **Автоматическая механическая проверка**:
   Запустите скрипт предварительной проверки целевого пакета или файлов:
   ```bash
   bash .agents/skills/rospanel-code-review/scripts/pre-review.sh ./internal/<package>/...
   ```
2. **Построчный анализ дифф-файлов**:
   Последовательно проверьте каждое изменение по категориям чеклиста ниже.
3. **Фиксация замечаний**:
   Оформляйте каждое замечание с точной ссылкой на `file:line` и описанием потенциального риска или регрессии.
4. **Формирование отчёта**:
   Группируйте замечания по уровням критичности:
   - **Must Fix**: блокирующие баги, гонки, утечки горутин/дескрипторов, нарушение инвариантов форка, рассинхрон i18n.
   - **Should Fix**: неоптимальные аллокации, избыточные блокировки, недостаточная обработка граничных условий.
   - **Nits**: стиль именования, мелкие неточности в комментариях.

## Чеклист проверки

### 1. Защита форка (Fork Safeguards)
- [ ] **Мульти-хоп**: не нарушена ли передача цепочек VLESS (вход → транзит → выход), сохранён ли диапазон портов `28443–28506` и логика обратных маршрутов (`reverse_guard.go`).
- [ ] **Лимиты устройств**: сохранена ли проверка `ActiveDeviceCountForUser` и завершение соединений при превышении лимита.
- [ ] **REALITY & Decoy**: не сломано ли совмещение портов по SNI на 443 порту; не включено ли HTTP/3 рекламирование; используются ли корректные пулы доноров.
- [ ] **Переменные окружения**: сохранена ли поддержка `ROSPANEL_REPO` для обновлений.

### 2. Конкурентность и жизненный цикл горутин
- [ ] **Остановка таймеров**: для всех `time.NewTicker` / `time.NewTimer` вызывается `defer ticker.Stop()`.
- [ ] **Завершение горутин**: у каждой запущенной через `go func()` горутины есть детерминированный выход по `ctx.Done()` или каналу остановки.
- [ ] **SSE и стримы**: обработчики долгоживущих соединений слушают `r.Context().Done()` и закрывают каналы при разрыве связи с клиентом.
- [ ] **Race conditions**: нет ли одновременного чтения и записи общих мап или полей без `sync.RWMutex`.

### 3. База данных SQLite и блокировки
- [ ] **Короткие транзакции**: транзакция (`store.Tx`) содержит только SQL-запросы; внутри транзакции **нет** сетевых вызовов (HTTP, gRPC, Telegram).
- [ ] **Закрытие курсоров**: для всех `store.Query` вызывается `defer rows.Close()`.
- [ ] **Идемпотентность DDL**: новые миграции используют `IF NOT EXISTS` и устойчивы к повторному добавлению колонок.
- [ ] **Шифрование**: секретные ключи, пароли и токены шифруются перед записью в БД.

### 4. Интернационализация (i18n)
- [ ] **Зеркалирование 5 языков**: если добавлен ключ в `internal/i18n/ru.go`, он присутствует в `en.go`, `ar.go`, `fa.go`, `zh.go`.
- [ ] **Порядок аргументов `Sprintf`**: количество и типы глаголов подстановки (`%s`, `%d`) строго совпадают во всех языках.
- [ ] **Генерация ошибок**: при изменении ошибок запущен `go generate ./internal/i18n/...`.
- [ ] **Тесты i18n**: проходит ли `go test -v ./internal/i18n/...`.

### 5. Сетевой уровень и конфигурации Xray
- [ ] **Валидность JSON**: конфигурации Xray не содержат пустых/фантомных секций для выключенных протоколов.
- [ ] **Безопасность портов**: нет ли коллизий между встроенными портами и пользовательскими inbounds.
- [ ] **Интеграционные тесты**: проходят ли тесты Xray (`RP_XRAY_BIN`).

### 6. Идиоматичный Go и обработка ошибок
- [ ] **Ошибки не игнорируются**: нет отбрасывания `_ = err` без комментария.
- [ ] **Оборачивание**: контекстные ошибки оборачиваются через `%w`.
- [ ] **Проверка ошибок**: используется `errors.Is` / `errors.As`.
- [ ] **Агрегация**: множественные ошибки агрегируются через `errors.Join`.
- [ ] **Форматирование**: код чист после `gofmt` и `go vet`.
