# Оркестрация и делегирование задач субагентам в RosPanel

Используйте этот навык при декомпозиции сложных, объёмных или параллельных задач, требующих изоляции рабочего пространства, глубокого аудита кода, сборки фронтенда или анализа апстрима.

---

## 1. Матрица принятия решений: Субагент vs Инлайн-исполнение

Субагенты создают накладные расходы на инициализацию и задержку ожидания. Делегируйте задачу субагенту только тогда, когда это даёт явный выигрыш в чистоте контекста или изоляции.

| Задача | Способ решения | Обоснование |
| :--- | :---: | :--- |
| **Точечный багфикс / правка 1–2 файлов** | **Инлайн** | В соответствии с [.agents/rules/surgical-editing.md](../../rules/surgical-editing.md) выполняется за 1 ход без накладных расходов. |
| **Код-ревью перед PR или релизом** | **Субагент** | Объёмные диффы и логи линтеров изолируются, основной контекст остаётся чистым. |
| **Синхронизация с Upstream (AppsGanin)** | **Субагент (`branch`)** | Тестирование слияния и анализ миграций в изолированной ветке без риска сломать рабочий каталог. |
| **Сборка и линтинг фронтенда (`web/`)** | **Субагент (`inherit`)** | Изолирует массивные логи Biome, `tsc` и `vite build` от Go-контекста. |
| **Матричное тестирование Xray (`RP_XRAY_BIN`)** | **Субагент (`inherit`)** | Генерирует длинные JSON и выводы валидатора, возвращая только результат PASS/FAIL. |
| **Правка единичной миграции SQLite** | **Инлайн** | Требует непрерывного контекста single-writer архитектуры; параллельная запись опасна. |

## 2. Специализированные роли субагентов RosPanel

Подробные шаблоны брифов для каждой роли находятся в [references/brief-templates.md](references/brief-templates.md).

### 2.1. `rospanel-reviewer` (Аудитор инвариантов и кода)
- **Цель**: Независимая проверка изменений по чеклисту [.agents/skills/rospanel-code-review/SKILL.md](../rospanel-code-review/SKILL.md).
- **Режим**: `Workspace: inherit`, Read-only.
- **Модель**: `inherit` или `pro`.
- **Что проверяет**: Защиту форка (Multi-Hop, REALITY 443 SNI, лимиты устройств), отсутствие гонок горутин, закрытие таймеров/курсоров, зеркалирование 5 языков i18n.
- **Выход**: Список дефектов `[P0]...[P3]` (Must Fix / Should Fix) или "No findings".

### 2.2. `upstream-auditor` (Аудитор слияния с Upstream)
- **Цель**: Анализ входящих коммитов из `AppsGanin/rospanel` по [.agents/skills/rospanel-sync-upstream/SKILL.md](../rospanel-sync-upstream/SKILL.md).
- **Режим**: `Workspace: branch` (**строго изолированная ветка**).
- **Модель**: `inherit`.
- **Что проверяет**: Пересечение номеров миграций SQLite, риск затирания Multi-Hop или пулов REALITY, добавление ключей локализации.
- **Выход**: Карта рисков, статус тестового слияния, рекомендации по перенумерации миграций.

### 2.3. `frontend-worker` (Фронтенд-инженер React 19)
- **Цель**: Разработка компонентов SPA, стилизация Tailwind v4, интернационализация по [.agents/skills/rospanel-frontend/SKILL.md](../rospanel-frontend/SKILL.md).
- **Режим**: `Workspace: inherit`.
- **Модель**: `inherit` или `flash`.
- **Обязательные проверки**: `npm run typecheck`, `npm run lint`, `npm run build`.
- **Выход**: Статус сборки и краткий список измененных компонентов.

### 2.4. `xray-validator` (Тестировщик сетевого стека)
- **Цель**: Проверка генерации конфигураций Xray по [.agents/skills/rospanel-xray-lab/SKILL.md](../rospanel-xray-lab/SKILL.md).
- **Режим**: `Workspace: inherit`.
- **Модель**: `flash` или `inherit`.
- **Что проверяет**: Отсутствие фантомных секций для выключенных протоколов, диапазон портов `28443–28506`, валидация с `RP_XRAY_BIN`.
- **Выход**: Статус тестов (PASS/FAIL) и фрагменты ошибочного JSON при сбоях.

## 3. Правила изоляции рабочих пространств (Workspace Safety)

При запуске субагента через `invoke_subagent` выбор режима `Workspace` критичен:

1. **`Workspace: branch` (Изолированная ветка)**:
   - **Когда использовать**: Слияния с апстримом, экспериментальные рефакторинги ядра, деструктивные тесты миграций.
   - **Защита**: Гарантирует, что незавершённые или конфликтные изменения не затронут рабочий каталог и Git-индекс.
2. **`Workspace: inherit` (Текущая рабочая копия)**:
   - **Когда использовать**: Статическое код-ревью (read-only), прогон линтеров, сборка фронтенда (`web/dist`).
   - **Ограничение**: Запрещено запускать одновременно двух субагентов с правом записи в одну и ту же директорию.
3. **Безопасность SQLite**:
   - RosPanel работает в режиме WAL на `modernc.org/sqlite` (single-writer).
   - Запрещено запускать параллельные субагенты, одновременно модифицирующие локальную базу данных `rospanel.db`.

## 4. Контракт составления брифа (Brief Contract)

Субагент не видит историю текущего диалога с пользователем. Бриф — это единственный источник контекста.

**Каждый бриф ОБЯЗАН содержать:**
1. **Явную ссылку на правила**: упомянуть `AGENTS.md` и специфичные правила проекта (например, `fork-safeguards.md` или `i18n-synchronization.md`).
2. **Ограничение области видимости (Scope)**: явно указать пути, которые субагент имеет право читать/модифицировать (например, «только директория `web/`»).
3. **Запрет на посторонние изменения**: субагент не должен рефакторить соседний код или менять форматирование вне зоны задачи.
4. **Сжатый формат ответа**: субагент должен возвращать структурированный итог (замечания по приоритетам, статус тестов), а не простыни терминального вывода.

---

## 5. Порядок обработки результатов субагента

1. **Получение уведомления**: Дождитесь завершения субагента (поллинг не требуется, система уведомит автоматически).
2. **Валидация отчета**:
   - Если субагент-ревьюер вернул замечания `[P0]` или `[P1]`, они должны быть устранены до коммита.
   - Если субагент-фронтендер изменил UI, убедитесь, что `web/dist` пересобран перед сборкой Go.
3. **Финальное решение**: Основной агент несёт ответственность за соблюдение архитектурных инвариантов RosPanel перед пользователем.
