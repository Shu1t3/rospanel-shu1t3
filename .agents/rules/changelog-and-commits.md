# Changelog and Commit Standards

## 1. Commit Messages Format
- Use Conventional Commits (`feat`, `fix`, `perf`, `refactor`, `docs`, `chore`) with an optional scope: `<type>(<scope>): <short summary>`.
- **Always provide a detailed body** with bulleted explanations:
  - **What changed:** specific files/modules and technical changes.
  - **Why:** problem solved or architectural motivation.
  - **Performance impact:** benchmarks, latency, memory allocations, or CPU savings where applicable.

## 2. Changelog Maintenance & Release PRs
- `release-please` extracts the commit header by default.
- When opening or merging a Release PR generated by `release-please`, **always enrich the release notes and `CHANGELOG.md`** with detailed sub-bullets extracted from commit bodies.
- For manual or unreleased additions in `CHANGELOG.md`, maintain structured entries under `## [Unreleased]` with:
  - Commit SHA and link.
  - Comprehensive technical description of features, bug fixes, or optimizations.
  - Impact on performance, architecture, or breaking changes.
