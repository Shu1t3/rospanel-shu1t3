# SQLite & Database Migrations Rules

В RosPanel используется чистый Go-драйвер SQLite (`modernc.org/sqlite` без CGO). База данных работает в режиме WAL (`Write-Ahead Logging`). 

---

## 1. Конкурентность SQLite и Lock Starvation

SQLite по своей природе поддерживает **только одного активного писателя (single-writer)**.
- **Никаких долгих транзакций**:
  - Транзакция (`s.Begin()` / `store.Tx`) должна содержать только быстрые операции чтения/записи в БД.
  - **Категорически запрещено** выполнять внутри открытой транзакции сетевые вызовы (HTTP к нодам, gRPC, вызовы Telegram API, обращение к внешним платежным шлюзам) или сложные дисковые операции.
- **Обработка `database is locked` / `busy`**:
  - Драйвер настроен с `busy_timeout`. Если горутины массово начинают параллельную запись, возникает lock starvation.
  - Массовые обновления данных (bulk update / bulk insert) выполняйте единым батчем внутри одной компактной транзакции, а не в цикле по отдельным транзакциям.
- **Очистка ресурсов**:
  - Всегда гарантируйте вызов `defer rows.Close()` сразу после успешного выполнения `Query` / `QueryRow`. Не оставляйте незакрытые курсоры.

---

## 2. Правила создания миграций

Все миграции располагаются в `internal/store/migrations/` в формате `NNNN_name.sql`.

### 2.1. Нумерация миграций
- При создании новой миграции проверяйте последний номер в папке.
- Чтобы избежать коллизий при параллельном слиянии с upstream, оставляйте запас по номерам или координируйте номер с последними изменениями апстрима.

### 2.2. Идемпотентность DDL
- Механизм мигратора RosPanel расширен для идемпотентного применения изменений (`migrations_idempotency_test.go`).
- Если миграция добавляет колонку (`ALTER TABLE ... ADD COLUMN ...`), мигратор должен корректно пережить сценарий, когда в восстанавливаемой базе эта колонка уже присутствует.
- При создании новых таблиц обязательно используйте:
  ```sql
  CREATE TABLE IF NOT EXISTS ...
  ```
- Для создания индексов обязательно используйте:
  ```sql
  CREATE INDEX IF NOT EXISTS ...
  ```

### 2.3. Шифрование чувствительных данных
- При добавлении в таблицы полей, содержащих приватные ключи, токены, пароли или учетные данные внешних сервисов, они должны сохраняться через встроенный слой шифрования (`store.Encryptor`).

---

## 3. Верификация изменений БД

После любых правок в `internal/store/` или добавления миграций обязательно выполнить:
```bash
go test -v ./internal/store/...
```
Тест `schema_version_test.go` проверяет актуальность последней версии схемы и встроенной `migrationsFS`.
