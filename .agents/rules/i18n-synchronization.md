# i18n & Localization Synchronization Rules

В RosPanel реализована строгая система интернационализации, охватывающая бэкенд, пользовательские страницы подписок, Telegram-ботов и React SPA админ-панели.

---

## 1. Поддерживаемые языки

Система поддерживает ровно **5 языков**:
1. `ru` — Русский (базовый/эталонный язык)
2. `en` — Английский
3. `fa` — Фарси (персидский, RTL)
4. `ar` — Арабский (RTL)
5. `zh` — Упрощённый китайский

---

## 2. Локализация бэкенда (`internal/i18n`)

### 2.1. Эталонный каталог `ru.go`
- `internal/i18n/ru.go` является эталоном (reference catalog).
- Все ключи структурированы по префиксам:
  * `sub.*` — страница подписки и профилей
  * `status.*` — страница статуса серверов
  * `bot.*` — Telegram-бот администратора
  * `user.*` — клиентский Telegram-бот
  * `err.*` — каталог системных ошибок

### 2.2. Правило синхронного зеркалирования
- Если в `ru.go` добавляется или изменяется ключ, он **обязан быть добавлен во все 4 зеркала**:
  * `internal/i18n/en.go`
  * `internal/i18n/ar.go`
  * `internal/i18n/fa.go`
  * `internal/i18n/zh.go`
- **Строгий порядок аргументов форматирования**: строки с подстановками (`%s`, `%d`, `%v`) должны сохранять точно такое же количество и порядок аргументов во всех языках. Несоответствие приводит к панике при `fmt.Sprintf`.

### 2.3. Каталог ошибок и кодогенерация
- При добавлении или изменении кодов ошибок в `internal/i18n/errcatalog.go` необходимо запустить кодогенерацию:
  ```bash
  go generate ./internal/i18n/...
  ```
  Это обновляет сгенерированный файл `internal/i18n/errcatalog_gen.go`.

### 2.4. Тестирование целостности
Тест `internal/i18n/callsites_test.go` проверяет кодовую базу на уровне AST:
```bash
go test -v ./internal/i18n/...
```
Тест завершится с ошибкой, если:
* В Go-коде вызван `i18n.T("some.key")`, которого нет в `ru.go`.
* В языковых зеркалах (`en`, `ar`, `fa`, `zh`) отсутствуют ключи из `ru.go`.

## 3. Локализация веб-панели (`web/src/i18n`)

### 3.1. Структура словарей фронтенда
Словари фронтенда находятся в:
* `web/src/i18n/ru.ts`
* `web/src/i18n/en.ts`
* `web/src/i18n/ar.ts`
* `web/src/i18n/fa.ts`
* `web/src/i18n/zh.ts`

### 3.2. Правила добавления UI-строк
- Запрещён хардкод пользовательских строк на английском или русском непосредственно в JSX/TSX компонентах. Всегда используйте хук `useTranslation()` и ключи `t('domain.key')`.
- При добавлении нового ключа в один из файлов локализации, он **атомарно добавляется во все остальные четыре файла**.
- После обновления словарей фронтенда запустите проверку типов:
  ```bash
  npm --prefix web run typecheck
  ```
