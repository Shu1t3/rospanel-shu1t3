# Переезд мастера и аварийное восстановление

Переезд сохраняет публичный домен мастера. Ссылки подписок, выданные через этот домен, не нужно рассылать заново: после смены DNS клиенты получат адрес нового сервера при обновлении подписки или повторном разрешении домена. Время переключения зависит от DNS-кэша и работы клиентских приложений.

## Подготовка

- Сохраните резервную копию мастера **вне старого сервера** и проверьте, что можете её прочитать.
- Подготовьте новый Linux-сервер и откройте требуемые порты панели и VPN-протоколов. Технический адрес кандидата задаётся в виде `IP:порт` (обычно порт `8080`); старый мастер должен иметь к нему доступ.
- Проверьте, что публичный домен мастера и все выданные ссылки используют доменное имя. Подготовьте доступ к управлению его A/AAAA-записями.
- Планируйте время на обновление DNS-кэша. Старый сервер должен оставаться доступен, пока клиенты обращаются к прежнему IP.

## Плановый переезд

1. На старом мастере откройте **Управление → Переезд мастера**. Укажите технический адрес кандидата и способ изменения DNS: вручную или через Cloudflare API.
2. Выполните на новом сервере **команду установки кандидата, сформированную панелью**. Она использует одноразовый токен сопряжения со сроком действия 15 минут. Команду не публикуйте.
3. Дождитесь готовности кандидата и запустите встроенные проверки. Если видите `connection refused`, проверьте, что сервис кандидата запущен, слушает указанный порт и доступен со старого мастера через firewall и сеть.
4. Дополнительно проверьте конфигурацию нового сервера: открытые порты протоколов, сертификат для публичного домена, сетевой маршрут и доступность нод. Встроенный preflight не выполняет полноценный тест каждого VPN-протокола или каждой ноды.
5. Запустите переключение в панели. Передача данных выполняется снимком SQLite. При ручном режиме DNS измените A/AAAA-записи домена на адрес нового сервера. Для Cloudflare проверьте фактическое состояние записей после операции.
6. Проверьте открытие панели, старых ссылок подписок, подключение VPN и синхронизацию нод через прежний домен. Оставьте старый сервер доступным до завершения перехода клиентов, затем выведите его из эксплуатации через панель.

Адрес кандидата не должен попадать в клиентские ссылки. Во время переезда избегайте изменений на обоих серверах вне панели. После появления новых данных на новом мастере простой возврат DNS на старый сервер может потерять эти изменения; перед откатом оцените состояние данных и сделайте резервную копию.

## Если мастер недоступен

Аварийное восстановление возможно только при наличии пригодной внешней копии. На новом сервере установите совместимый бинарник и выполните:

```bash
sudo rospanel disaster-recover --from /path/to/rospanel-backup.tar.gz
# Для копии, защищённой паролем:
sudo rospanel disaster-recover --from /path/to/rospanel-backup.tar.gz --passphrase 'пароль'
sudo systemctl restart rospanel
```

Команда подготавливает восстановление и выводит домен, секретный путь и оценку потери данных по времени создания копии. После перезапуска проверьте панель и обновите A/AAAA-записи прежнего домена на новый сервер. Данные, созданные после последней копии, восстановить из неё нельзя.

Локальную копию можно создать командой `rospanel backup /path/to/backup.tar.gz`. Храните отдельную копию вне сервера и периодически проверяйте восстановление.
