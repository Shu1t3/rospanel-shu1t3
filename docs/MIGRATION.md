# Руководство по переезду мастер-ноды и аварийному восстановлению

В этом документе описан регламент планового переезда мастер-ноды RosPanel на другой сервер, порядок действий при авариях и процедуры отката.

---

## 1. Архитектура и гарантии

### Сохранение контрактов клиентов
- **Публичный домен:** остаётся прежним (например, `vpn.example.com`). Не подменяется техническим адресом кандидата.
- **URL подписок:** формат `https://<домен>/<путь>/<пользовательский_токен>` и выданные конфигурации (Base64, Clash, sing-box, Xray JSON) сохраняются **байт-в-байт**. Пользователям и клиентским приложениям не требуется повторный импорт или смена ссылок.
- **Подключение обычных нод:** ноды подключаются к тому же публичному домену и продолжают синхронизацию без повторного join-токена.

### Предотвращение Split-Brain (Fencing)
- Допустим только **один активный мастер**.
- В момент финального переключения старый мастер переходит в состояние **Fenced**: немедленно блокируются любые операции мутации (HTTP 503 `server_fenced`), фоновые процессы биллинга, Telegram-боты, выдача токенов и приём отчётов.
- Финальный снимок создается через SQLite WAL checkpoint (`PRAGMA wal_checkpoint(TRUNCATE)`) + `VACUUM INTO`, гарантируя 100% консистентность базы и шифрованных секретов (`secrets.key`).

### Окно DNS-кеширования (Standby Mode)
- Так как DNS не обновляется мгновенно во всем мире, старый сервер автоматически переводится в режим **Standby**:
  - VPN-службы на старом IP продолжают работать для клиентов с закешированным DNS.
  - Все запросы к панели управления, API и подпискам прозрачно проксируются на новый активный мастер.
  - Трафик клиентов учитывается единожды без дублирования.

## 2. Плановый переезд (Planned Migration)

### Шаг 1: Подготовка
1. Войдите в панель управления на текущем мастере: `Настройки` → `Управление` → **«Переезд мастера»**.
2. Укажите:
   - **Технический адрес кандидата:** IP и порт нового сервера (например, `203.0.113.10:8080`). Этот адрес нужен только для передачи снимка и предстартовых проверок.
   - **Режим DNS:**
     - *Cloudflare API:* автоматическое понижение TTL до 60 секунд за несколько часов до переезда и мгновенная смена A/AAAA записей.
     - *Вручную (Manual):* ручная смена записей у регистратора с предупреждением о DNS-кеше.
3. Нажмите **«Создать переезд»**. Панель сформирует одноразовый защищенный токен спаривания (срок действия: 15 минут).

### Шаг 2: Развертывание кандидата одной командой
На новом (целевом) сервере выполните сгенерированную команду от имени root:
```bash
curl -Ls https://raw.githubusercontent.com/Shu1t3/rospanel-shu1t3/main/install.sh | sudo bash -s -- \
  --candidate "203.0.113.10:8080" \
  --master "https://vpn.example.com" \
  --pair-token "<короткоживущий_токен>"
```
Кандидат запустится в пассивном режиме ожидания снимка.

### Шаг 3: Проверка готовности (Verification Checklist)
В веб-интерфейсе нажмите **«Запустить проверки»**. Система автоматически проконтролирует:
- Доступность API кандидата по техническому адресу;
- Сохранение контракта URL подписок и соответствие токенов;
- Доступность портов каждого включенного протокола (VLESS, REALITY, Hysteria2 и др.);
- Наличие и валидность TLS-сертификата для публичного домена;
- Доступность обычных нод кластера;
- Целостность SQLite снимка и расшифровку секретов.

Кнопка **«Переключить на новый мастер»** станет активной только после успешного прохождения всех обязательных проверок.

### Шаг 4: Переключение (Switchover)
1. Нажмите **«Переключить на новый мастер»** и подтвердите действие.
2. Система:
   - Включит блокировку изменений (Fencing) на старом мастере;
   - Передаст финальный дельта-снимок;
   - Повысит кандидата до активного мастера (`RoleMaster`);
   - Переключит DNS-записи (A/AAAA) на новый IP;
   - Переведёт старый сервер в режим ожидания (`RoleStandby`).

### Шаг 5: Мониторинг Standby и вывод из эксплуатации
1. В окне переезда отображается блок **«Режим ожидания (Standby)»**:
   - Число активных клиентов, обращающихся к старому IP;
   - Время последнего обращения;
   - Прошедшее время с момента переключения DNS.
2. После истечения времени жизни DNS-записей (обычно 1–2 часа) число активных клиентов на старом IP снизится до 0.
3. Нажмите **«Отключить старый сервер»**. Временные токены спаривания удаляются, службы старого мастера окончательно останавливаются.

## 3. Процедуры отката (Rollback)

### Вариант А: Откат ДО смены DNS (Фазы Prepare / Candidate Ready)
Если в процессе синхронизации или проверок обнаружена проблема:
1. Нажмите кнопку **«Откатить переезд»** в интерфейсе (или вызовите `POST /api/migration/rollback`).
2. Старый мастер снимает блокировку мутаций, сессия переезда переходит в `rolled_back`.
3. Кандидат останавливается. База данных старого мастера остаётся нетронутой.

### Вариант Б: Откат ПОСЛЕ смены DNS (до окончательного отключения)
Если сразу после смены DNS на новом мастере возник критический сбой сетевой связности:
1. Нажмите **«Откатить переезд»**.
2. DNS переключается обратно на старый IP.
3. Старый мастер разблокируется (`SetFenced(false)`) и возобновляет полный контроль.
> **Внимание!** Если на новом мастере уже были совершены пользовательские операции (покупки, регистрации), возврат на старый мастер приведет к потере этих операций, так как старая база была заморожена.

## 4. Аварийное восстановление (Disaster Recovery)

Если старый мастер **полностью уничтожен, физически недоступен или скомпрометирован**, переезд выполняется из внешней резервной копии.

### Создание и тестирование резервных копий
- Резервные копии создаются локально и экспортируются во внешнее защищенное хранилище (S3/WebDAV/монтированный диск).
- Поддерживается симметричное шифрование AES-256-GCM.
- Для проверки целостности копии без риска для рабочей базы доступна кнопка **«Пробное восстановление в песочнице»** (или вызов `backup.TrialRestoreSandbox`), выполняющая проверку заголовков, версии схемы и `PRAGMA quick_check(1)`.

### Восстановление нового мастера одной командой
На чистом сервере с установленным бинарником RosPanel выполните:
```bash
sudo rospanel disaster-recover \
  --backup /var/backups/rospanel-latest.tar.gz \
  --domain vpn.example.com \
  --listen :443
```
Если резервная копия была зашифрована паролем:
```bash
sudo rospanel disaster-recover \
  --backup /var/backups/rospanel-latest.tar.gz.enc \
  --decrypt-pass "ваш_пароль_шифрования" \
  --domain vpn.example.com \
  --listen :443
```

Команда:
1. Расшифровывает и распаковывает архив;
2. Проверяет SQLite базу на отсутствие повреждений (`quick_check`);
3. Восстанавливает `secrets.key` с правами `0600`;
4. Восстанавливает сертификаты TLS и ACME-аккаунты;
5. Запускает RosPanel в режиме активного мастера.

После запуска обновите A/AAAA запись домена `vpn.example.com` на IP нового сервера. Клиенты и ноды автоматически переподключатся после обновления DNS.
