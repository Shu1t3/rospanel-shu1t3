# Мульти-хоп

Мульти-хоп — отдельный VLESS-профиль в подписке. Клиент подключается к первому серверу, а тот передаёт трафик по цепочке в заданном порядке. Последний сервер выпускает трафик в интернет. Список может состоять из одного сервера, который одновременно служит входом и выходом.

## Настройка тестовой группы

1. Откройте **Серверы → Мульти-хоп → Создать маршрут**. Укажите имя и выберите первым сервер в стране клиента.
2. Выберите выход. Чтобы вставить транзитный сервер перед выходом, нажмите **+ Добавить сервер**. Стрелками меняйте порядок, кнопкой **×** удаляйте лишние позиции. Каждый сервер можно включить в маршрут один раз.
3. Включите VLESS TCP-TLS на всех серверах после входа. Каждому серверу нужен сетевой доступ к TCP-порту VLESS следующего сервера. Для новых маршрутов и изменений обновите агенты участвующих нод до версии с поддержкой подтверждений применения.
4. Сохраните маршрут и выдайте тестовой группе доступ к нему в **Группах доступа**. Дождитесь, пока исчезнет статус **Применяется**. Обновите подписку в клиентском приложении и выберите профиль с именем маршрута.
5. Проверьте, что запрос выходит с IP последнего сервера. При смене входа обновите подписку повторно. При изменении только серверов после входа адрес, порт и UUID клиента сохраняются.

## Как применяется маршрут

- Панель применяет новую цепочку от выхода к входу. Каждая нода подтверждает, что её Xray принял конфигурацию. До подтверждения готовности входа подписка продолжает указывать на прежний маршрут, если он уже был опубликован.
- Каждое межсерверное соединение использует отдельные служебные учётные данные и принимает трафик только с адресов предыдущего сервера. Промежуточный сервер направляет трафик к следующему звену. Если звено недоступно, трафик обрывается. Пользовательский трафик учитывается один раз на входе.
- Маршруты v5.6.0 открываются как список из трёх серверов с прежним портом, UUID и правами группы. Цепочки произвольной длины редактируются в форме **Мульти-хоп**. Старые интеграции могут продолжать использовать поля `transit` и `exit` для профилей, сохранённых в прежнем формате.
- Количество позиций ограничено числом подходящих серверов. На Linux проверены маршруты из 1, 2, 3, 5 и 12 серверов для TCP и UDP. Проверка подтверждения конфигурации не заменяет клиентскую проверку доступности цепочки по сети.

## Нагрузка на синхронизацию

В замере Linux ARM64 на 50 000 пользователей полный сжатый Xray-конфиг вырос с 276 КБ до 1,51 МБ на входе с одним дополнительным маршрутом. На транзите с одним служебным подключением объём составил 277 КБ. Замер охватывает генерацию и сжатие конфига. При одновременном доступе к обычному и мульти-хоп-профилю вход может получать полную синхронизацию из-за разных UUID одного пользователя.

## Защищённый маршрут через R

Режим **Защищённый маршрут через R** предназначен для схемы `клиент → A → R → B → R → C → сайт`. A — вход в стране клиента, R — зарубежный ретранслятор, B — транзитный VPS, C — местный выход. C сам устанавливает обратный VLESS-туннель `C → R → B`. B передаёт запросы C по этому туннелю. A и C могут быть одним сервером. B должен быть отдельной нодой, чтобы подключение агента к панели не стало прямым соединением с B. Если A, B и C размещены на одном стенде, вынесите B в отдельный Ethernet-сегмент. В общей сети служебные объявления IPv6 от B видны соседям даже при работающих фильтрах Xray.

### Развёртывание

1. Обновите панель и агентов A, R, B, C. Используйте Xray v26.10.21, Linux с `nft` и права `CAP_NET_ADMIN` для агентов. В контейнере ограничения действуют в его сетевом пространстве имён. Если на хосте есть другие процессы, которые могут соединяться с B, продублируйте блокировку на хосте или внешнем фаерволе.
2. Проверьте маршрут R → B. Предпочтителен частный адрес B, доступный из R. Выпишите исходящие IPv4 и IPv6, с которых R действительно приходит на B, и все адреса B, которые нужно блокировать на A и C. Если B использует DNS с несколькими A/AAAA-записями, укажите их все. Нужны свободные служебные TCP-порты на R и B. На внешнем фаерволе откройте порт R для A и C, а порт B только для адресов R. Настройте отдельно IPv4 и IPv6. RosPanel повторно применяет свою таблицу nftables каждые 5 секунд. Чтобы защитить и промежуток после сброса таблицы, настройте независимые ограничения на уровне сети. На B они разрешают вход на служебный порт только с R, а на A и C блокируют соединения с IP B.
3. Включите режим в форме мульти-хопа и назначьте роли. В поле **Адрес B для соединения от R** введите один IP. В списках укажите остальные IP B и адреса R, которые видит B. Если старый маршрут использовал B напрямую, сначала выключите его. При неизменном A сохраняются ID, порт, UUID и клиентский профиль. Для изменения действующего защищённого маршрута со старым и новым набором ролей выберите свободные служебные порты для нового развёртывания.
4. Сохраните маршрут. Панель сначала настраивает слушатели R и B, затем запускает туннель C и переключает вход A. Подписка публикует клиентский адрес A. После исчезновения статуса **Применяется** проверьте работу клиентским запросом. B и A/C применяют сетевые правила до запуска новой конфигурации Xray. На B разрешены только перечисленные источники R, на A/C запрещены прямые соединения с адресами B.
5. Сравните публичный IP из двух запросов к одному внешнему сервису определения IP. Первый выполните с обычным клиентским профилем через A, второй напрямую из сети C. Затем отдельно откройте целевой сайт из сети C. Если сайт блокирует провайдер C, зарубежный транзит сам по себе доступ не восстановит. На A и C снимите пакеты на внешних интерфейсах при запуске и повторном соединении. Ожидаются соединения с R и отсутствие пакетов к адресам B. Проверьте порт B с R и другого хоста. По очереди остановите R и C и проверьте ошибку клиентского запроса и восстановление.

У A и C отдельные VLESS-учётные данные для соединения с R и для доступа к B. R пересылает только TCP на заданный IP и порт B. Участок до B защищён отдельной TLS-сессией через `dialerProxy`. На B пользовательский трафик закреплён за `reverse-out`, на C обратный вход — за отдельным `freedom`. Учётные данные получаются из серверного ключа штатным механизмом межсерверных подключений и не входят в клиентскую подписку. [Документация Xray по dialerProxy](https://xtls.github.io/en/config/transports/sockopt.html#sockoptobject) · [Примеры обратного VLESS](https://xtls.github.io/en/document/level-2/vless_reverse.html)

### Откат

Выключите защищённый маршрут в форме и дождитесь обновления A, R, B и C. Закройте служебные порты во внешнем фаерволе. Если требуется прежний маршрут, восстановите порядок серверов и выключите защищённый режим у того же профиля. При возврате старой версии панели сначала отключите защищённый маршрут и убедитесь, что агенты убрали его из действующих конфигураций.
